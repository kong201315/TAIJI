## 三、纠错与修复过程

### 3.1 修复 server.js

**游离 `1`（第 14 行）**

```diff
-const DATA_FILE = path.join(DIR, 'data.json');
-1

+const DATA_FILE = path.join(DIR, 'data.json');

```

**`saveData()` / `db` 时序调整**：把 `let db = loadData();` 提到 `saveData` 定义之前，消除"引用未声明变量"的脆弱依赖。

```diff

-function saveData() { ... }      // 此时 db 尚未声明
-
-let db = loadData();
-if (!fs.existsSync(DATA_FILE)) saveData();
+let db = loadData();              // 先初始化
+
+function saveData() { ... }      // 再定义，引用已就绪的 db
+
+if (!fs.existsSync(DATA_FILE)) saveData();
```

### 3.2 清理测试残留（最大阻力点：文件被进程占用）

首次 `rm -rf _edge_cdp` 报大量 `Device or resource busy`——**目录被一个仍在运行的 headless Edge 测试进程占用**（这正是 `_cleanup.ps1` 原本要清理的对象）。

诊断：用 `Get-CimInstance Win32_Process` 定位，确认进程为：
`msedge.exe --headless --remote-debugging-port=9222 --user-data-dir=.../_edge_cdp`（PID 3292 及其 14 个子进程），确认为自动化测试浏览器、非正常浏览会话。

处理：
1. `taskkill /PID 3292 /T /F` 终止进程树
2. 重新 `rm -rf _edge_cdp`，删除成功（185MB）

同时删除 `_cdp_test.js`、`_cleanup.ps1`。

## 六、经验沉淀

- `node --check` / `new Function()` 只校验语法，**合法但无意义的死代码（如游离的裸数字）不会报错**，仍需人工审查。
- Windows 下删除目录报 `Device or resource busy` 时，多为进程占用；用进程命令行特征（如 `--user-data-dir`、`--headless`、`--remote-debugging`）定位占用者，而非盲目重试。
- 单文件 SPA 的内联脚本可用「提取 `<script>` 内容 → `new Function()` 校验」的方式做快速语法体检。
